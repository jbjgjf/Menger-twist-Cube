# Certified Solver for the Inner-Square Move System

`level3-inner-square-certified` and `level4-inner-square-certified` read only the current state and solve the full move group generated by slices, extensions, and additional inner-square turns.
At Level 2, the existing `level2-certified` solver already handles the expanded move system. At Level 1, there are no additional inner-square targets, so the two move systems coincide.

## Execution

```sh
npm run bench -- --level=3 --seeds=101 --length=100
npm run bench:inner-square -- 3 1000 101 all
npm run bench:inner-square -- 3 0 101 certified direct
```

The first command runs the standard benchmark CLI; the second runs the research CLI comparing the certified solver, Variant D, and hierarchical block restoration on identical inputs; the third performs direct state construction independent of random-walk mixing.
When comparing against the legacy `level3-slice-reduction` or `level4-slice-reduction` solvers, pass `--move-system=standard` explicitly.
The Lab also defaults to the new move system: it passes the move system to the worker and rejects incompatible algorithms before execution.

## Procedure

1. Compute position orbits and local orientation stabilizer groups from the full generator set.
2. Normalize the joint signature of orbit parities and abelianized orientations using a $\mathbb{Z}_4 / \mathbb{Z}_3$ basis straight-line program (SLP).
3. Complete the even permutation on each orbit using conjugates and commutators of pure 3-cycle tools.
4. Complete orientations using two-site tools for $C_3$ and $C_4$, rotation and reflection tools for $D_4$, and a final commutator.
5. Replay every output atomic move independently in a sparse integer representation and require exact agreement on all positions and orientations.

On large orbits, the solver uses a table of color pairs over legacy orbits: it repeatedly transports two sites within the legacy group to witness positions and applies a single new generator that changes their color pair.
This relies on the legacy tool certificates and an exhaustive check of all color-pair edges; see the [constructive proof](../proofs/inner-square-completeness.md#d1-transport-using-legacy-orbit-independence) for details.

## Hierarchical Block Restoration and Variant D

`level3-block-restoration` and `level4-block-restoration` accept the same expanded move system.
Coarse inner-square turns are first expanded into words on three fine planes before verifying their support and action.
If block restoration succeeds, the solver solves the coarse quotient problem; otherwise it falls back to the certified solver above.
For search depth $L$, restoration deficit $D$, and single-move change bound $K$, the search is safely skipped whenever $D > L \cdot K$.
At all levels, Variant D (commuting cancellation across moves with disjoint selection supports) is applied as a final pass.

When block-restoration search is skipped on deep random inputs and yields the exact same move count as Variant D alone, we do not count that as an improvement from hierarchical structure.
Success on shallow structured inputs and efficiency on deep inputs are recorded separately.

## Source Files

- `mengerAbelianSignature.ts`: joint signature, SLP evaluation, and basis auditing.
- `mengerInnerSquareReduction.ts`: complete reduction of positions and orientations.
- `mengerFactoredTransport.ts`: large-orbit transport via color pairs of legacy orbits.
- `innerSquareTools.json`: discovered tools audited across their full action.
- `innerSquareCertifiedSolver.ts`: input-model verification and solver API.
- `mengerBlockRestoration.ts` / `higherBlockRestorationSolver.ts`: restoration search and lifting.
- `research/inner-square-expanded/`: exhaustive enumeration, computational certificates, experiments, and raw data.

Because independent replay inspects every output move, replaying tens of millions of moves at Level 4 requires substantial time.
The current output is a flat array of atomic moves; neither short optimal solutions nor large-scale replay in the browser is guaranteed.

Even if the legacy move system is removed from the UI or public API, color-pair transport internally relies on the subgroup spanned by the legacy generators and its tool certificates. Although research scrambles use the expanded move system, the internal legacy subgroup must be retained as a dependency of the constructive solver.

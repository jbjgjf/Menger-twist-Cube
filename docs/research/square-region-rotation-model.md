## 0. この文書の位置づけ

既存モデル（`packages/engine/src/frameDefinitions.ts` と `turnTargets.ts` が生成する324候補、
うち合法156対象＝468原子手）と、その合法性判定（`packages/engine/src/rotationLegality.ts`）は
**一切変更していない**。本文書が定義するのは、既存候補生成とは独立に

> 「同一平面内のブロック群の外形が正方形であり、その正方形の中心を通る垂直軸のまわりに
> 回転しても、静止しているブロックと衝突しないもの」

を列挙する**監査用の拡張モデル**である。実装は `research/square-rotation/` 配下にのみ存在し、
Play・ソルバー・既存テスト・既存証明のいずれも参照していない。

既存証明との関係は [`square-region-rotation-impact.md`](./square-region-rotation-impact.md) に分離した。

## 1. 記号

レベル $n$、格子一辺 $N=3^n$、`extent` $e=(N-1)/2$、整数座標範囲は $[-e,e]^3$。
メンガー位置集合を $P_n$（$|P_n|=20^n$、レベル2で400、レベル3で8000）とする。

軸 $a\in\{X,Y,Z\}$ に対し、軸方向座標を $p_a$、面内2座標を $(u,v)$ と書く。面内座標の順序は
`rotationLegality.ts` の `axisBasis` に合わせ、$X\to(y,z)$、$Y\to(z,x)$、$Z\to(x,y)$ とする。

**層（plane）** とは $p_a=\ell$ を満たす $P_n$ の部分集合をいう。

## 2. 候補生成の定義（何を列挙するか）

候補は組 $(a,\ell,c,S)$ である。$a$ は軸、$\ell$ は層座標、$c=(c_u,c_v)$ は面内の軸位置、
$S\subset P_n$ は選択セル集合（すべて $p_a=\ell$）。角度 $\theta\in\{90^\circ,-90^\circ,180^\circ\}$
は候補に対して別に与える。

主モデルは**一層**に限定し、次の二族を列挙する。

### 2.1 族 `region`（最小モデル）

面内の軸平行正方形格子領域
$R=[m_u,m_u+s-1]\times[m_v,m_v+s-1]$（$1\le s\le N$）を取り、

$$S=\{p\in P_n : p_a=\ell,\ (p_u,p_v)\in R\},\qquad c=\Bigl(m_u+\tfrac{s-1}{2},\ m_v+\tfrac{s-1}{2}\Bigr)$$

とする。$S$ は領域内の**全メンガーセル**である。穴および非連結は、どのセルが存在するかを
メンガー集合が決めるので自動的に許される。$S=\varnothing$ の領域と、より小さい領域と
（同一 $c$ で）同一の $S$ を与える領域は除去する。

### 2.2 族 `subset`（網羅モデル）

$S$ を、外接箱が $c$ を中心とする正方形になる**任意の**部分集合とする。これは
ユーザーの一般条件そのものであり、族 `region` を真に含む。有限列挙できる理由は §5 に置く。

### 2.3 軸位置の格子

$c_u,c_v$ は**ともに整数**（辺長が奇数）か**ともに半整数**（辺長が偶数）に限る。片方だけ半整数
の組は、90度回転が整数格子を整数格子に写さないため候補になり得ない（180度回転では格子を保つが、
その場合 $u$ 方向のセル数が偶数・$v$ 方向が奇数となり外接箱が正方形になり得ない）。

半整数中心は採用する。$c=(a+\tfrac12,b+\tfrac12)$（$a,b$ は整数）まわりの90度回転は

$$(x,y)\longmapsto\bigl(a+b+1-y,\ x+b-a\bigr)$$

であり、整数格子を整数格子へ写す（中心自身は $(a+\tfrac12,b+\tfrac12)$ に留まる）。
レベル2では一層あたり $9^2+8^2=145$ の軸位置を列挙している（全体中心を通る軸は
そのうちの1つに過ぎない）。

### 2.4 採用した仮定の一覧

| 項目 | 採用した定義 |
| --- | --- |
| 正方形の意味 | **選択セル群の外接箱**が正方形かつ中心が軸上。穴あり領域も可。領域の外形ではなく選択セルの外形で判定する（エンジンの `outerEnvelopeIsSquare` と同一） |
| 領域内の選択 | 全セル（族 `region`）と任意の部分集合（族 `subset`）の**両方**を列挙 |
| 中心・辺長の格子 | 整数中心と半整数中心の両方。混合中心は除外（理由は §2.3） |
| 回転軸 | X/Y/Z に平行な単位軸のみ。全体中心を通らない軸を含む |
| 層の厚み | 主モデルは一層。厚み付きは別枠（§7） |
| 角度 | 90、-90、180 のすべて。180 でも正方形条件を課す（§6.2） |
| 180度の回転の向き | 判定器は正の向きの掃過しか検査しない。物理的にはどちらの向きで回しても同じ終状態になるので、どちらかの向きで通れば合法とするのが自然である。レベル2では −180 でだけ通る集合が0件だったので、この二つの定義は一致する（2026-09-23 検査） |
| 終点閉包 | 要求する。回転後の位置集合が元の集合と一致しなければ不合法 |
| 境界接触 | 許す。正の体積を持つ侵入のみ禁止（エンジンの厳密内部比較と同一） |
| 外形のみ検査との関係 | エンジンは外形だけでなく**全選択セル**を対で検査する。二つの検査は一般には同値でない（合成反例あり）。ただしレベル2の候補では差0件（§6.1） |
| 状態依存性 | 合法性は占有位置集合だけで決まる（§4） |

## 3. 合法性の定義（候補をどう判定するか）

合法性は**既存エンジンの判定器に委ねる**。監査側で幾何判定を再実装していない。具体的には、
候補 $(a,\ell,c,S)$ と角度 $\theta$ から $S$ をちょうど選択する合成 `TurnTarget` を作り、
`validateTurnTargetRotation` を呼ぶ。判定器の三段は

1. **外形（`outer-envelope-not-square`）** $|\theta|=90$ のとき、$S$ の外接箱が正方形で
   その中心が軸上にあること。
2. **終点閉包（`endpoint-not-closed`）** $\theta$ 回転が $S$ の位置集合を $S$ 自身へ
   一対一に写すこと。
3. **連続衝突（`sweep-collision`）** 各セルを閉単位立方体とし、回転中の掃過体の内部が
   静止セルの内部と交わらないこと。境界接触は合法。

である。主モデルではこれに加えて、監査側で $|\theta|=180$ でも外形正方形条件を明示的に課す
（理由は §6.2）。

## 4. 合法性は占有位置集合だけで決まる

**命題。** 到達可能な任意の状態において、候補と角度の合法性は完成状態における判定と一致する。

**根拠。** (i) `validateRigidRotationUncached` は `cubie.currentPosition` のみを読む
（`id` はメッセージ文字列にしか現れない）。したがって判定は占有位置の多重集合と候補・角度の
関数である。(ii) 合法手はこの多重集合を保存する。終点閉包により動くセルは自分たちの位置集合の
中で置換され、静止セルは動かないからである。

**実測。** 6 seed × 400 合法手（既存合法手からの乱択）で、占有位置集合の変化 0、既存合法手集合の
差 0、監査候補の判定差 0/8964。判定は毎回新規ターゲットを生成して行い、エンジンの `WeakMap`
キャッシュが差を隠さないようにしている（`research/square-rotation/legality-invariance.ts`）。

これにより、候補列挙と差分監査は完成状態上で一度だけ行えばよい。

## 5. 族 `subset` の有限網羅性

部分集合は原理的には $2^{|{\rm layer}|}$ 通りだが、合法性から強い閉包条件が出るため
閉集合だけを列挙すれば足りる。

**補題（回転閉包）。** 合法な $S$ は、$c$ まわりの $\theta$ 回転の**軌道の合併**であり、
かつ各軌道の全セルが占有されている。

*理由.* 終点閉包そのもの。軌道の一部が非占有なら閉包は成立し得ない。

**補題（対分解）。** $S$ が掃過衝突を起こさないことは、
「$S$ のセル $m$ と $S$ 外のセル $k$ の対がどれも衝突しない」ことと同値である。

*理由.* 剛体回転の掃過体は各単位立方体の掃過体の合併であり、静止体も各立方体の合併なので、
交差の非空性は対ごとの交差の非空性の論理和に等しい。動くセル同士は同一の剛体運動に従うので
衝突しない。判定器の実装も、同一軸座標の (動くセル, 静止セル) 対を走査しており、この分解と
一致する。

**系（含意閉包）。** 軌道 $O$ を動かすとき、$O$ が掃過する別の軌道 $O'$ も動かさなければ
ならない。よって合法な $S$ は含意関係 $O\to O'$ の**前方閉集合**であり、かつ「絶対に動かせない
セル」（軌道が占有で閉じないセル）を掃過する軌道を含まない。

**系（90度の外形条件は自動）。** 90度回転の各軌道の外接箱は $c$ を中心とする正方形であり、
同心正方形の合併は同心正方形である。したがって $|\theta|=90$ では外形条件は常に成立する。
180度では軌道サイズが2なので外接箱を明示的に検査する。

列挙は、含意関係の強連結成分を縮約した DAG 上で「後続を先に決める」順に走査する。各部分割当は
（残りを全部除外すれば）少なくとも一つの閉集合に延長できるので、走査コストは
$O(\text{閉集合数}\times\text{成分数})$ に収まり $2^{\text{軌道数}}$ にならない。

含意関係 $O\to O'$ 自体も、監査側の幾何計算ではなく**エンジンに問い合わせて**得る。$O$ と $O'$
だけを含む世界を作って `validateTurnTargetRotation` を呼ぶと、外形（軌道は同心正方形）と
終点閉包（軌道は閉じる）は必ず通るので、掃過衝突段だけが失敗し得る。

**打ち切り方針。** 軸位置・角度あたりの閉集合数に上限 $10^6$ を設け、超過した場合はその軸位置を
「未網羅」として件数と軌道数を記録する。レベル2・レベル3とも上限に当たった軸位置は0件である。

**検算。** 列挙した閉集合はすべて、完成状態の**全**セルに対してエンジンで再判定している
（レベル2で 459/459 が合法）。また族 `region` の合法候補が族 `subset` の列挙に含まれること
（0件の欠落）も検査している。これは上の閉包論法を信用せず検査に落とすためである。

## 6. 判定器の仕様に依存する二点

### 6.1 外形のみの検査と全選択セルの検査は同値ではない

判定器は外形（外接箱）を**候補の早期棄却**にのみ使い、衝突検査は全選択セルに対して行う。
外接箱だけの衝突検査で十分か（外形を構成するセルだけ調べれば内部セルは安全か）は本監査では
**証明していない**ので、両者を区別して扱う。監査が使うのは全選択セルの検査である。

**2026-09-23 追記.** 二つの検査は**一般には同値でない**。選択範囲の穴に静止セルがあると、そのセルに衝突し得るのは
内部の移動セルだけだからである。合成配置の反例をテストに固定した：角4セル＋内部軌道4セルを選び、$(1,1)$ に静止セルを置く。
判定器は全セル検査では衝突、外形だけの検査では合法と判定する。一方、レベル2の Menger 配置の候補（族 `region`・`subset` で終点閉包を通る5,439組）では、
両検査の判定差は**0件**だった（実測、`envelope-only-check.ts`）。

### 6.2 180度では判定器が外形を検査しない

`rotationLegality.ts` は

```ts
if (Math.abs(angle) === 90 && !outerEnvelopeIsSquare(moving, candidate.pivot, basis)) {
```

と書かれており、180度では外形段を通らない。したがって**長方形断面の180度回転**が判定器を
通り得る。これはユーザーの一般条件（正方形の中心を通る軸）の外側なので、主モデルからは
監査側で明示的に除外し、別カテゴリとして計数する（レベル2で24原子手、すべて $1\times3$ 箱の
2セル対）。

## 7. 対象外（今回のモデルに含めないもの）

| 対象外 | 理由と扱い |
| --- | --- |
| X/Y/Z 以外の軸（面対角・体対角） | 判定器が `unsupported-axis` で必ず拒否する。監査用の別判定器を新規実装することは「実装上の検査通過と厳密な無衝突証明を区別する」制約と衝突するため、次フェーズの検討事項とする |
| 厚み付き（複数層）回転 | 別枠として計数のみ（`research/square-rotation/extensions-count.ts`）。連続する層・同一断面の角柱に限定して列挙した。層ごとに断面が異なる剛体や非連続層は対象外 |
| 長方形断面の180度回転 | 別枠として計数のみ（§6.2） |
| 厚み付きの部分集合族 | 未実装。厚み付きは `region` 相当の角柱のみ |
| レベル3全体の網羅監査 | 次フェーズ。所要時間は**標本からの外挿**（`region` 族は451,044候補のうち1,996候補＝0.44%を判定して全体約1274秒と外挿、`subset` 族は $Z=0$ 面1面の実測439msを81面へ外挿して約36秒、heap 約1.5GB は実測） |

## 9. 数値誤差・近似・キャッシュの前提

- **許容誤差** `geometryEpsilon = 1e-9`。比較は厳密内部比較なので境界接触は合法側に落ちる。
  座標は整数・半整数のみを扱うため、`roundToGrid` による丸めは監査の範囲では誤差を生じない。
- **連続衝突判定の近似** 掃過検査は頂点円弧の厳密な角度境界で区間を棄却し、残る区間を
  深さ16まで二分する（90度回転で約0.0014度分解）。棄却は厳密だが、**「合法」という判定は
  数学的な無衝突証明ではない**。深さ上限内で中点が内部重なりを示さなかったことを意味するに
  すぎない。本監査はこの判定器の出力を「実装上の検査通過」として扱い、厳密証明とは区別する。
- **キャッシュ** `cachedValidation` は (ターゲット実体, 角度) で結果を保持し、四分の一回転が
  `legal` または `sweep-collision` のとき90/-90/180に同じ結論を書き込む。監査は候補ごとに
  新規ターゲットを生成するので既存候補のキャッシュと混ざらない。さらに角度の問い合わせ順序を
  4通り（90/-90/180、180/90/-90、-90/180/90、180/-90/90）変えて全6180候補を再判定し、
  判定差0を確認している（`research/square-rotation/cache-assumption.ts`）。
- **メモリ・時間** レベル2の全監査は約10秒、heap 100MB 未満。レベル3の見積りは §7 のとおり。
  2026-09-23 の再実行（`npm run audit:square`）は14.5秒、RSS 311MB で、出力は保存済みの結果と一致した（違いはタイムスタンプのみ）。
- **厳密化（2026-09-23 追記）** 上の「合法は証明ではない」という制約は、レベル2の一層モデルでは解消した。
  $H$ の全522原子手は、整数演算による円環分離で無衝突を証明した。網羅性の根拠である衝突判定58,236件は、すべて有理数角での
  厳密な分離軸判定で衝突を証明した。詳細は [`square-region-rotation-impact.md`](./square-region-rotation-impact.md) §6.2。
  **残る近似** 円環分離は十分条件にすぎない。レベル3で分離できない合法対が現れた場合、その対については判定器の判定しか根拠がない。
